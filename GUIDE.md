# Путевые листы ЭСМ-2 — автоматизация. Гайд с нуля

Что это: набор Python-скриптов, которые автоматизируют обработку путевых листов
строительной техники (форма ЭСМ-2) и их привязку в 1С.

## Из чего состоит проект

| Файл | Что делает | Когда запускать |
|---|---|---|
| `waybill_app.py` | **Главное приложение.** Веб-интерфейс для оператора: сканы → автозаполнение из 1С → печать | Постоянно, на компьютере рядом со сканером |
| `monitor_pl.py` | Фоновый скрипт: находит в 1С заказы без путевого, читает штрихкод со скана, пишет штрихкод обратно в 1С | Постоянно, на машине с доступом и к 1С API, и к сетевой шаре сканов |
| `calibrate_zones.py` | Разовый инструмент: визуально подвинуть/добавить/удалить зоны полей на скане, получить готовый код для `SCAN_FIELDS` | Только когда разъехалась калибровка полей |
| `check_scan.py` | Разовый инструмент: посмотреть, что AI считает заполненным/пустым на конкретном скане | Для отладки детекции |
| `test_pl_barcode.py` | Безопасная ручная версия `monitor_pl.py` — с кнопкой подтверждения перед каждой записью в 1С | Разово, для проверки перед боевым запуском `monitor_pl.py` |
| `test_barcode.py` | Крошечный тест: просто прочитать штрихкод из одного файла | Для быстрой диагностики |
| `template_esm2.pdf` | Пустой эталонный бланк ЭСМ-2 | Используется `waybill_app.py` внутри, не трогать |

## Установка на новом компьютере

1. Python 3.10+ должен быть установлен.
2. Поставить зависимости:
   ```
   pip install -r requirements.txt
   ```
3. Для `pyzbar` на Windows нужна DLL zbar — обычно ставится вместе с pyzbar,
   если нет — https://github.com/NaturalHistoryMuseum/pyzbar#windows
4. Скопировать `.env.example` → `.env`, заполнить реальными паролями (спросить
   у Александра/из старого `.env`, если он есть — **никогда не коммитить `.env` в git**).
5. В `waybill_app.py` найти строку `SCAN_FOLDER = r"C:\Scans"` — это папка,
   куда сканер сохраняет файлы. Поменять на актуальную для нового компьютера.

## Как пользоваться `waybill_app.py` (основной инструмент)

Запуск:
```
python waybill_app.py
```
Откроется браузер на `http://127.0.0.1:8765`.

**Обычный сценарий:**
1. Кладёте скан путевого листа в папку `C:\Scans` (или жмёте кнопку
   «↑ Загрузить файлы вручную» на главной странице и выбираете файл).
2. Приложение само: читает штрихкод → запрашивает данные заказа в 1С →
   AI смотрит скан и определяет, что уже заполнено от руки → открывает
   новую вкладку браузера с этим путевым.
3. На странице путевого: слева — скан, справа — форма.
   - **Серая рамка / бейдж «на скане»** — поле уже заполнено от руки на скане,
     ничего печатать сюда не будем.
   - **Зелёная рамка / бейдж «из 1С»** — данные подтянулись из 1С автоматически.
   - **Красная рамка** — пусто, нужно заполнить руками.
4. Начинаете печатать в поле — на скане слева сразу появляется жёлтая
   подпись с текстом (live-превью). Если она легла не туда — **тащите её
   мышкой** прямо по картинке, куда нужно.
5. Для полной копии на чистом листе нажмите **«🖨 Распечатать копию со сканом»**:
   PDF содержит скан вместе с дополнениями. Для допечатки на исходном путевом
   нажмите зелёную кнопку **«🖨 Допечатать на оригинале»** — в новой вкладке
   открывается PDF только с новыми надписями на пустой странице. Скан,
   рукописные записи и бланк в этот PDF не включаются.
6. Вставьте в принтер исходный бумажный путевой той стороной и в том направлении,
   которые соответствуют предпросмотру. Печатайте в масштабе **100% / «Фактический
   размер»**, без подгонки под страницу. Сначала распечатайте на пробном чистом
   листе и приложите к оригиналу на просвет, чтобы проверить расположение текста.
   При необходимости поправьте позиции надписей в предпросмотре.

Если анализ заполненных полей завершился ошибкой или отсутствует, печать
блокируется: повторно загрузите скан для анализа. Перед печатью проверьте,
что новые надписи в предпросмотре не перекрывают рукописные записи.

**Имя и сохранение PDF:** под полями путевого расположен блок «Сохранение PDF».
Заказчик заполняется полными реквизитами: после `working_shift_barcode` приложение
берёт `КлиентКод` и выполняет `POST /kocode?code=...`. Поле
`ПредставлениеПокупателя` используется в форме и печати, а короткое
`КлиентНаименование` — в автоматическом имени PDF. Если код отсутствует или
сервис реквизитов недоступен, остаётся краткое название и показывается предупреждение.
У ранее загруженных путевых нажмите «Обновить реквизиты заказчика из 1С»;
это перезагрузит страницу и заменит реквизиты заказчика (несохранённые правки
формы потеряются). Организация больше не подставляется константой: пока API
не передаёт организацию-исполнителя, её реквизиты вводятся вручную.
Старое фиксированное значение организации не переносится в форму автоматически.

Имя по умолчанию состоит из заказчика и даты в формате `ДД,ММ`; его можно
изменить, например на `КОРСТРОЙ ООО 48 ед 04,09`. Часть `48 ед` автоматически
не определяется: отдельного подтверждённого поля номера техники в используемом
ответе API нет. Нажмите «Сохранить копию PDF» или «Сохранить допечатку PDF»:
браузер скачает файл с выбранным именем. К имени допечатки добавляется
` — допечатка`, чтобы отличать её от полной копии. Расширение `.pdf` добавляется
автоматически. Папка скачивания и показ окна выбора места зависят от настроек
браузера. Исходный файл скана не переименовывается. Кнопки печати по-прежнему
открывают PDF для просмотра; для сохранения с заданным именем используйте
кнопки сохранения в приложении.

**Кнопки над сканом:**
- «Стр. 1» / «Стр. 2» — переключение страниц скана.
- «📐 Сетка координат» — открывает скан с линейкой в pt (для отладки координат).
- «🔲 Разметка полей» — подсвечивает все зоны детектирования цветом.

**Главная страница** (`/`): список ожидающих обработки путевых, кнопка
«↻ Загрузить из папки» — подхватить файлы, которые уже лежат в `C:\Scans`,
но почему-то не открылись сами.

**Служебная страница `/calibration-report`**: показывает, сколько раз
операторы двигали каждое поле при печати и не пора ли поправить координаты
по умолчанию. Автоматически применяет поправку, если на поле накопилось
≥20 перетаскиваний (см. `CALIBRATE_MIN_SAMPLES` в `.env`) — без перезапуска.

### Важно: перезапуск после любой правки кода

Python не подхватывает изменения файла в уже запущенном процессе.
После **любой** правки `waybill_app.py`:
1. Остановить процесс (Ctrl+C в окне, где он запущен, или закрыть окно).
2. Запустить заново: `python waybill_app.py`.

Иначе браузер продолжит работать по старому коду в памяти процесса.

## Как пользоваться `monitor_pl.py` (фоновая привязка штрихкодов)

**Что делает**: раз в `POLL_INTERVAL_SEC` секунд спрашивает 1С «какие заказы
за последние `DATE_RANGE_DAYS` дней ещё без путевого», идёт по указанному
1С пути к файлу скана на сетевой шаре, читает штрихкод, пишет его в 1С.

**Важно про сеть**: этому скрипту нужен доступ ОДНОВРЕМЕННО и к сетевой шаре
сканов (`\\1C-SQL\Scans`), и к API 1С (`77.51.227.6:80`). Если запустить с
машины, у которой есть только один из двух — часть работы будет тихо
проваливаться (в логе будет видно `Файл не найден` или `Ошибка получения
заказов`). Проверить доступность обоих одной командой не получится — надо
просто попробовать запустить и посмотреть лог.

**Запуск (ВСЕГДА сначала в сухом режиме!):**
1. В `.env` убедиться, что `DRY_RUN=1`.
2. `python monitor_pl.py`
3. Смотреть `monitor_pl.log` — в конце каждого цикла есть строка
   `Итог: written=N, file_missing=N, no_barcode=N, ...` — по ней видно,
   сколько бы реально записалось.
4. Только когда цифры выглядят разумно — поставить `DRY_RUN=0` в `.env` и
   перезапустить.

**Настройки скорости разбора очереди** (в `.env`):
- `MAX_ORDERS_PER_RUN` — не больше скольких заказов за один цикл (по
  умолчанию 50, чтобы не бомбить 1С и шару разом).
- Если нужно быстро разобрать большой накопившийся хвост старых заказов —
  можно временно поднять `MAX_ORDERS_PER_RUN` до 150-200 и снизить
  `POLL_INTERVAL_SEC` до 120-180, а после того как очередь схлопнется —
  обязательно вернуть обратно 50 / 600.

**`test_pl_barcode.py`** — та же логика, но с ручным подтверждением каждой
записи через браузер (кнопка «Записать ШК в 1С» на каждой строке). Полезно
как более безопасная альтернатива первому боевому запуску `monitor_pl.py`.

## Известные ограничения (на 24.07.2026)

Монитор штрихкодов сохраняет прогресс в `monitor_pl_queue.json`: сначала проверяет
ещё не просмотренные смены, затем повторяет ранее просмотренные, начиная с самых
давних попыток. Ошибки и отсутствие файла не блокируют переход к старым сменам.
Прогресс сохраняется после каждой попытки и переживает перезапуск. Идентификатор
смены и путь к скану образуют ключ очереди; новый путь считается новой записью.
Запускайте только один экземпляр `monitor_pl.py` в папке проекта.

Для старых смен увеличьте `DATE_RANGE_DAYS` в `.env`, например до `90`, и
перезапустите монитор. Он обходит только записи, которые возвращает 1С за
запрошенный период, порциями по `MAX_ORDERS_PER_RUN`. Между порциями ждёт
`POLL_INTERVAL_SEC` секунд. После полного обхода оставшиеся записи проверяются
повторно. `DRY_RUN=1` означает проверку без записи; такие результаты в сводке
показываются отдельно от успешных записей в 1С.

- Форма поддерживает **до 3 дней** работы на один путевой (не 6, как в
  бланке) — сознательно сокращено, редко нужно больше.
- Дата составления и «Период работы с/по» **не участвуют** в live-превью
  (нет жёлтой подписи при наборе) — печатаются по координатам по умолчанию,
  без возможности перетащить.
- Запись подтверждённых данных путевого обратно в 1С **не реализована**
  (только печать). Заглушка `save_to_1c()` в коде есть, но не вызывается —
  сознательное решение, endpoint для этого пока не обсуждался.
- Раз поймали редкую порчу кодировки текста при печати (судя по всему —
  из-за одновременной фоновой обработки нового скана и печати в разных
  потоках). Добавлена блокировка (`_pdf_lock`) вокруг операций с PDF,
  должна была устранить, но стопроцентной гарантии нет — если увидите
  на печати иероглифы вместо кириллицы, попробуйте распечатать ещё раз.

## Если что-то не работает

1. Смотреть консоль, где запущен `waybill_app.py` / `monitor_pl.py` — там
   подробный лог на русском по каждому шагу.
2. Проверить, что сервер реально перезапущен после последней правки кода.
3. `/calibration-report` — если текст на печати не туда попадает у многих
   операторов, посмотреть сюда.
4. Если поля печатаются не в том месте на новом типе скана (другой
   сканер/разрешение) — `python calibrate_zones.py "путь\к\скану.pdf"`,
   подвигать зоны, скопировать сгенерированный код в `SCAN_FIELDS` в
   `waybill_app.py`, перезапустить.
